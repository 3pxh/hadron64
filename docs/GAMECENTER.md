# Game Center integration

Status: **designed and stubbed, not switched on.** All Game Center code lives in
`Hadron64/GameCenter/GameCenterService.swift` and is a no-op while
`GameCenterService.isEnabled == false`. The app's own `StatsStore` stays the source of truth;
Game Center only receives copies of finished games.

## What players get

| Feature | How |
|---|---|
| All-time leaderboards | One Classic leaderboard per public mode |
| Daily leaderboards | One Recurring leaderboard per public mode, resetting every 24h |
| Friends' scores | `loadEntries(for: .friendsOnly, …)` on either board |
| Adding friends | Apple's friend-request sheet (`presentFriendRequestCreator`) |
| Dashboard | `GKAccessPoint` badge on the home screen (hidden during play) |

## Leaderboards

Public modes only. Training modes (Simple Cards, Remainder, Remainder Matching, Set Size) stay
personal; they're practice and would split the player base.

| Mode | Leaderboard IDs | Score | Format | Sort |
|---|---|---|---|---|
| Free Play | `h64.freeplay.alltime`, `h64.freeplay.daily` | deck time in hundredths of a second | Elapsed Time – to the hundredth | Low → high |
| Time Trial Easy | `h64.timetrial.easy.alltime`, `.daily` | cards collected | Integer | High → low |
| Time Trial Medium | `h64.timetrial.medium.alltime`, `.daily` | cards collected | Integer | High → low |
| Time Trial Hard | `h64.timetrial.hard.alltime`, `.daily` | cards collected | Integer | High → low |

The IDs are generated by `Leaderboard.allTimeID(_:)` / `Leaderboard.dailyID(_:)`; keep them in sync
with App Store Connect. Scores come from `Leaderboard.score(for:)`.

What gets submitted:

- Free Play: only **completed** decks with **no hints**. Leaving mid-game records nothing.
- Time Trial: every game that ends (deck cleared or clock out). Hints don't exist there.
- Each game goes to both its all-time and daily board in one `GKLeaderboard.submitScore` call.
  Game Center keeps each player's best per board, so we submit every game, not just records.

Daily boards use Game Center's **Recurring** leaderboards: start date at 00:00 UTC, duration 1 day,
"recurrence" repeating. Game Center handles the rollover; the app doesn't need to know the date.
(One global UTC reset is the platform constraint; there's no per-player local midnight.)

## Flow

1. **Launch** – `Hadron64App` calls `GameCenterService.shared.authenticate()` from `.task`. It installs
   `GKLocalPlayer.local.authenticateHandler`; if Game Center hands back a sign-in view controller we
   present it on the top-most controller. On success the access point is shown top-leading.
2. **Play** – `GameScreen` hides the access point on appear and restores it on disappear so the badge
   never covers cards.
3. **Finish** – `DeckGame.finish` → `onFinish` → `StatsStore.log(_ game:)` → `GameCenterService.submit`.
   Local records and leaderboards share one choke point, so they can't disagree about what counted.
4. **Friends** – `requestFriendsAccess()` triggers the system friends-list permission prompt
   (`NSGKFriendListUsageDescription` is already in Info.plist). `friendEntries(mode:daily:)` returns
   the local player's entry plus friends' entries for an in-app list. `presentAddFriends()` opens
   Apple's friend-request UI; friend management itself always happens in Game Center.
5. **Full boards** – `presentLeaderboard(for:)` opens `GKGameCenterViewController` scoped to friends.

## Turning it on

1. In Xcode, add the **Game Center** capability to the `Hadron64` target (adds the
   `com.apple.developer.game-center` entitlement). With XcodeGen, add to `project.yml`:
   ```yaml
   entitlements:
     path: Hadron64/Hadron64.entitlements
     properties:
       com.apple.developer.game-center: true
   ```
2. In App Store Connect → the app → Game Center, enable Game Center and create the 8 leaderboards
   from the table above (4 Classic + 4 Recurring daily), with localized names and score formats.
3. Set `GameCenterService.isEnabled = true`.
4. Test with a sandbox Game Center account on a device; leaderboards created in App Store Connect
   are visible to development builds before release.

## Notes and edge cases

- **Offline**: `submitScore` failures are logged; GameKit queues and retries submissions itself.
- **Cheating**: scores are client-reported. Free Play times under ~60 s for a full deck are almost
  certainly impossible; App Store Connect lets you set a score range per leaderboard to reject them.
- **Hints**: hinted Free Play games are excluded from records and leaderboards (see
  `GameRecord.usedHints`), so the boards stay comparable.
- **Rule changes**: if deck size or timings ever change, create new leaderboard IDs (e.g. `h64.v2.…`)
  rather than mixing incomparable scores.
